# Topics Covered

## 1. Bean Validation

Implemented validation using:

- @Valid
- @NotBlank

Example:

```java
@NotBlank(message = "Batch name cannot be empty")
private String batchName;
```

---

## 2. @Valid

Used @Valid in Controller methods to automatically validate incoming request bodies before executing business logic.

Example:

```java
@PostMapping
public ResponseEntity<Batch> saveBatch(@Valid @RequestBody Batch batch) {
    ...
}
```

---

## 3. ResourceNotFoundException

Created a custom exception to handle missing resources.

Example:

```java
throw new ResourceNotFoundException("Batch not found with id: " + id);
```

---

## 4. Global Exception Handler

Created a centralized exception handler using:

```java
@ControllerAdvice
```

Handled:

- ResourceNotFoundException
- MethodArgumentNotValidException

---

## 5. Validation Exception Handling

Implemented:

```java
@ExceptionHandler(MethodArgumentNotValidException.class)
```

Collected validation errors using:

- BindingResult
- FieldError

Returned errors as:

```json
{
  "batchName": "Batch name cannot be empty"
}
```

# Important Concepts Learned

## ResponseEntity

Used ResponseEntity to send both:

- HTTP Status Code
- Response Body

Examples:

| Status | Meaning |
|---------|----------|
| 200 | OK |
| 201 | Created |
| 204 | No Content |
| 400 | Bad Request |
| 404 | Not Found |

---

## BindingResult

Stores all validation errors generated by Spring.

---

## FieldError

Represents validation failure for one field.

Contains:

- Field Name
- Rejected Value
- Validation Message

---

## Why Map<String,String>?

Used:

```java
Map<String,String>
```

to return

```json
{
  "fieldName": "Validation Message"
}
```

instead of

```json
[
  "Validation Message"
]
```

This makes it easier for frontend applications to display field-specific errors.
